# Football3 New Engine V1 — Reuse Boundary

Status: PREREGISTERED_BEFORE_IMPLEMENTATION

## Allowed reuse
- Historical raw match data already present or regenerated by an existing legal/public collector.
- Canonical team/competition identity machinery.
- Existing PIT timestamp and fail-closed governance concepts/utilities.
- Feature lineage, logging, receipt hashing and generic evaluation metric utilities when they contain no fitted model state.
- Legacy V500/R43 code/output only behind an isolated comparison boundary for same-match benchmarking.

## Forbidden inside the new model core
- Any fitted coefficient, latent state, hyperparameter selected from a legacy sealed/test set, model pickle, serialized estimator or weight from V500/R43.
- Any legacy prediction matrix or probability vector as a New Engine training target or feature.
- Any outcome generated by a legacy model as a label.
- Copying the legacy prediction algorithm and renaming/wrapping it as New Engine V1.
- Reading market/odds fields from the pure-football module.
- Reading target/current-match final lineup, post-kickoff information or future observations.

## Proof obligations
Automated guards must verify that the pure core has no import dependency on legacy model modules and no market/odds input. The new implementation must live under `football-data/new_engine_v1/`; legacy paths are read-only comparison dependencies and are never modified by this branch.

If independence cannot be demonstrated, execution stops and no candidate claim is allowed.
