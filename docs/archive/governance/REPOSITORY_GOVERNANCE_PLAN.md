## 8. Five-workflow convergence design

### `.github/workflows/ci.yml`
- Triggers: `pull_request`; optional `push` to main only for read-only verification.
- Permission: `contents: read` only.
- Runs syntax, unit, schema, source-of-truth pointer, workflow-policy, and receipt-integrity checks.
- Never trains models; never writes repository state; never creates commits.
- Concurrency: `ci-${{ github.ref }}`; `cancel-in-progress: true`.

### `.github/workflows/research.yml`
- Trigger: `workflow_dispatch` and/or PR-controlled invocation; **no automatic push-to-main research execution**.
- Permission: `contents: read`; artifacts write through Actions artifact service only.
- One `task_id` maps to exactly one research PR and one formal research receipt.
- All model outputs, logs, metrics, and generated receipts are uploaded as artifacts; no direct commit to main.
- Long tasks use task/ref concurrency and `cancel-in-progress: true`.
- Promotion is impossible inside this workflow; promotion requires a separate reviewed PR.

### `.github/workflows/scheduled-data.yml`
- Trigger: `schedule + workflow_dispatch`; no push-triggered persistence.
- Collects/validates external PIT data, weekly team configuration, market snapshots, and other scheduled evidence.
- Output is artifact/staging payload only. Durable repository persistence is performed through a separate PR.
- One schedule owner per data family; no duplicate fallback schedulers.
- Concurrency keyed by data family/date; `cancel-in-progress: true` for long refreshes.

### `.github/workflows/forward.yml`
- Trigger: controlled `schedule + workflow_dispatch`; disabled/manual-only while the current governance freeze is active.
- Owns future PIT freeze, official settlement, and forward audit when re-enabled after review.
- No direct main push. Freeze/evaluation ledgers are artifacts first; durable updates go through a dedicated persistence PR.
- A single forward execution owner replaces duplicated current owners/fallbacks.
- Concurrency keyed by forward epoch; `cancel-in-progress: true`.

### `.github/workflows/maintenance.yml`
- Trigger: `schedule + workflow_dispatch`; may also validate governance on PRs.
- Runs stale-PR detection, registry integrity, workflow-policy lint, source-of-truth checks, artifact-retention checks, and repository health metrics.
- Default `contents: read`. Any future PR creation uses narrowly scoped pull-request permission and never direct main push.
- No model training or model evaluation.
- Concurrency: repository-wide maintenance group; `cancel-in-progress: true`.

## 9. Non-negotiable repository rules

1. Any workflow triggered by `push` is forbidden from executing `git commit`, `git push`, or an indirect helper that persists back to the triggering branch.
2. Ordinary CI must use `contents: read` only.
3. Research results are saved as GitHub Actions artifacts; they are not committed directly to main.
4. Any result that must become durable repository state must enter through a separate, reviewable PR.
5. Workflows are forbidden from directly pushing to `main`.
6. One research task may have only one PR and one canonical formal research receipt.
7. Completed or failed research PRs may not remain open indefinitely; the registry must carry a close/archive deadline/state.
8. Every workflow must define `concurrency`.
9. Long-running tasks must set `cancel-in-progress: true`.
10. No research/model workflow can promote itself or mutate formal CURRENT.
11. No workflow may create another workflow as a side effect.
12. No workflow may use bot-written main commits as its normal event bus.

## 10. Design for `football-data/RESEARCH_REGISTRY.json` (design only; not created in Phase 1)

Purpose: one machine-readable index for every research task so task identity, PR, code hash, data freeze, result artifact, final receipt, and closure state cannot drift across branches.
```json
{
  "schema_version": "repository-research-registry-v1",
  "generated_at_utc": "<timestamp>",
  "governance_state": "PAUSED_FOR_REPOSITORY_GOVERNANCE",
  "formal_current_version": "V5.0.1",
  "tasks": [
    {
      "task_id": "R-YYYYMMDD-NNN",
      "title": "<single research objective>",
      "target": "90m_1x2|direct_total_goals|exact_score|data_only|other",
      "research_version": "<version>",
      "formal_weight": 0,
      "status": "PLANNED|RUNNING|FINAL_PASS|FINAL_FAIL|ABORTED|ARCHIVED",
      "pr_number": 0,
      "head_branch": "<branch>",
      "base_sha": "<sha>",
      "code_sha": "<sha>",
      "data_freeze": {"id": "<freeze-id>", "sha256": "<sha256>"},
      "workflow": "research.yml",
      "artifact_run_ids": [],
      "canonical_receipt_path": "<one path only>",
      "result_summary": {},
      "promotion_state": "NOT_ELIGIBLE|REVIEW_REQUIRED|REJECTED|PROMOTED",
      "merged_to_main": false,
      "completed_at_utc": null,
      "close_state": "OPEN|READY_TO_CLOSE|CLOSED",
      "supersedes_task_id": null
    }
  ]
}
```
Registry invariants:
- `task_id`, PR, and canonical receipt are one-to-one.
